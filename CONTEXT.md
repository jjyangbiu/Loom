# CONTEXT — Loom · 对话即生成单页应用的智能体平台

> 术语表（Glossary）。只收录领域概念，不含实现细节。实现决策见 `docs/adr/`。

| 术语                           | 定义                                                                                                                                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 项目（Project）                | 用户创建的应用构建单元，拥有一组生成文件、一段对话历史、一种生成模式与一个属主用户。                                                                                                                          |
| 生成文件（File）               | 智能体为项目产出的应用源文件（HTML / CSS / JS 等），项目与文件是一对多关系。                                                                                                                                  |
| 智能体（Agent）                | 代表用户规划、拆解需求并编写代码的 AI 角色。                                                                                                                                                                  |
| 工程师模式（Engineer Mode）    | 单一工程师智能体根据用户描述编写代码的快速模式；项目尚无文件时先经需求澄清与共识确认再生成。                                                                                                                  |
| 团队模式（Team Mode）          | 多智能体全流程模式：澄清智能体做需求澄清，规格智能体产出需求规格，拆单智能体拆解工单，用户逐级确认后由工程师智能体按检查点串行执行。                                                                          |
| PRD                            | 产品经理智能体产出的产品需求文档，团队模式旧流程中的确认对象；新流程中由需求规格承接其职责，仅存在于历史项目。                                                                                                |
| 迭代（Iteration）              | 用户对已生成的应用通过对话持续修改的过程。只有产生实际文件改动的轮次才形成新的版本快照；纯问答轮与零改动轮不留档。                                                                                            |
| 首建轮（First-Build Round）    | 项目尚无文件、需求共识已确认后的那一轮生成，从零产出整个应用。不存在增量修改语义（没有旧文件可越界），因此不进意图识别。                                                                                        |
| 迭代轮（Iteration Round）      | 项目已有文件时落到工程师智能体的用户对话轮，是增量修改语义与意图识别的唯一作用域。克隆项目的第一条消息也算迭代轮——克隆的语义就是"在已有文件上继续迭代"。                                                      |
| 增量修改（Incremental Modification） | 迭代中对已生成应用的修改只触及用户本轮明确指出的区域或元素，文件其余部分保持原样；是衡量迭代可靠性的核心判据，对应“改 A 别动 B 和 C”的用户期望。                                                              |
| 意图识别（Intent Recognition） | 迭代轮开始时的一次独立分类调用，判定本轮是要求改动代码还是仅作问答/闲聊，据此决定该轮智能体是否被授予写文件的能力。不替代既有的确定性阶段分流，也不作用于首建轮与团队工单执行。                                  |
| 意图（Intent）                 | 意图识别的二值结果：改动代码（modify_code，授予写文件能力）或咨询（consult，仅授予只读能力）。分类器只决定**能力边界**、不决定**义务**——改动代码轮仍可自报"无需改动"收尾。不确定时一律判为改动代码。           |
| 只读工具集（Read-only Toolset）| 咨询轮绑定的工具集，物理上不含写文件工具，使模型无法改动文件；与澄清智能体"不绑任何文件工具"是同一手法——不靠劝说，靠能力缺失。                                                                                |
| 改动范围契约（Change Scope Contract） | 迭代轮的事前承诺与事后核验的成对机制：轮次开始时声明用户目标与预期触及文件，轮次结束时由系统用磁盘真实 diff 核验。使"越界改动"首次成为机器可判定的事，不再依赖用户肉眼比对。                             |
| 轮前指纹（Pre-Round Fingerprint）     | 迭代轮开始时项目全部文件状态的留档，轮末据以算出本轮真实改动了哪些文件，是改动范围契约的核验基准。基准是**磁盘状态**而非上一个版本快照——两者可能脱钩。                                                   |
| 自洽性核验（Self-Consistency Check）  | 轮末比对智能体自己声明的改动与磁盘上真实发生的改动，判定它是否说了真话。不依赖对模型措辞的猜测，取代"口头完成"的中文正则检测。                                                                           |
| 正确性裁决（Correctness Verdict）     | 轮末由独立裁判比对用户原始诉求与真实改动，判定改的是不是该改的：范围内 / 越界 / 未完成。裁判不得看见智能体的自述，否则退化为自证清白。                                                                   |
| 需求澄清（Clarification）      | 尚无文件的项目中，智能体在生成前与用户分轮问答、彻底弄清模糊需求的对话阶段；需求充分清晰或用户要求跳过时结束。                                                                                                |
| 澄清答案标记（clarify_answer） | 弹窗式澄清中用户答案消息的持久化标记（kind=clarify_answer）：历史回看据此把答案折叠进问答记录卡，与“新请求”区分；后端上下文与分流语义与普通用户消息一致。                                                     |
| 需求共识（Consensus）          | 工程师模式中需求澄清结束时智能体产出的需求摘要，经用户确认后工程师开始生成。                                                                                                                                  |
| 需求规格（Spec）               | 团队模式中澄清完成后由规格智能体产出的结构化需求文档，经用户确认后才进入工单拆解。                                                                                                                            |
| 工单（Ticket）                 | 需求规格拆解出的纵向执行单元，每个都是可独立预览的完整路径；清单以卡片呈现（标题/交付内容/被谁阻塞/状态）并经用户确认后才进入执行期；一经确认不可重新拆单，后续按依赖顺序串行执行，每完成一个形成一个检查点。 |
| 检查点（Checkpoint）           | 每个工单执行完成后形成的版本快照，属版本快照体系，可预览与回滚；回滚后从未完成工单重新执行。                                                                                                                  |
| 版本快照（Snapshot）           | 某次成功生成后项目全部文件的完整留档，可被查看、对比（diff）与回滚；回滚本身也留档为新版本（内容与目标版本一致，历史只增不减；目标与最新快照内容一致时不留档），回滚后后续迭代基于该版本继续。                                                                                                          |
| 迭代日志（Iteration Log）       | 按「改动」而非「对话轮」累积的摘要：每次产生文件改动的轮次记一条（用户目标的蒸馏复述、改了哪些文件、核验结论）；咨询轮不入账。不截断，注入模型上下文，弥补对话窗口截断导致的语义脉络丢失，使模型在后续轮次仍能理解早期迭代的意图。        |
| 预览（Preview）                | 项目属主在登录态下查看当前版本应用运行效果的界面。                                                                                                                                                            |
| 发布（Publish）                | 将项目的当前版本转化为一个稳定的、任何人无需登录即可访问的公开链接。                                                                                                                                          |
| App 世界（App World）          | 所有已发布应用的公开画廊，支持浏览、语义搜索与克隆。                                                                                                                                                          |
| 克隆（Clone）                  | 将他人已发布的项目完整复制到自己名下，成为可继续迭代的新项目。                                                                                                                                                |
| 模板知识库（Template Library） | 预置的优质应用模板与技术片段集合，供生成前检索以增强生成质量；优质已发布应用可沉淀入库。                                                                                                                      |
| 官方示例（Official Sample）    | 由系统自身生成并发布进 App 世界的示例应用，用于画廊冷启动与克隆演示。                                                                                                                                         |
